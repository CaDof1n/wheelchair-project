# 接口标准自检清单 · 第六大组 · 架构与接口规范单元

**用途**：任何人改动接口标准、注册表或 `wheelchair_interfaces` 包之后，按本清单自查一遍再提交。
**适用版本**：IW-IF-STD-001 **V1.0**（标签 `v1.0.0`）。

> **别做的事**：不要凭记忆改接口字段；不要直接 push 到 `main` / `develop`（分支保护会拒绝）；
> **在整机通过「连续 50 次空载 + 50~70 kg 沙袋配重」测试之前，任何人不得坐在轮椅上通电或做动态测试**（任务书安全红线）。自检不涉及硬件，不要顺手去动车。

## 自检 1 · 接口包构建（**最优先**）

这是**目前唯一没有验证过的交付物**。`wheelchair_interfaces` 的接口定义转录自标准附录 A，
但从未在真实 ROS 2 里构建过。**它编译不过，五个组的仿真包全都构建不了**，第 8 周期中演示会直接卡住。

环境：Ubuntu 22.04 + **ROS 2 Humble**（Humble 的官方支持发行版只有 Ubuntu 22.04 等，
**Arch / CachyOS 不在官方支持列表里**，见下面的说明）。

> ### 非 Ubuntu 环境（Arch / CachyOS / Manjaro）先读这段
>
> 官方二进制只发 Ubuntu。Arch 系要装 Humble 只能走 AUR 的 `ros2-humble`
> （`yay -S ros2-humble`）。**这条路以折腾著称**：需要 `pybind11`、有 SIP4/SIP6 冲突、
> Python 3.12 之后 `rosidl_typesupport_fastrtps_c/_cpp` 会构建失败、`colcon --cmake-args -Wno-dev`
> 参数报错……建议**不要在 AUR 上硬磕**。
>
> **更省事的是容器**，一行就能拿到干净的 Humble，且不动你本机一根毫毛：
>
> ```bash
> # Arch 上先装容器运行时（任选其一）
> sudo pacman -S docker && sudo systemctl enable --now docker && sudo usermod -aG docker $USER
> # 或者用 rootless 的 podman：sudo pacman -S podman —— 下面把 docker 换成 podman 即可
>
> # 把只有源码的 wheelchair_ws/src 拷进容器里构建，产物不落回宿主机（避免 root 属主的 build/）
> docker run --rm -v "$PWD/wheelchair_ws/src":/src:ro -w /tmp ros:humble-ros-base bash -c '
>   apt-get update && apt-get install -y python3-colcon-common-extensions >/dev/null && \
>   cp -r /src /tmp/ws && cd /tmp/ws && \
>   colcon build --symlink-install --packages-select wheelchair_interfaces && \
>   source install/setup.bash && \
>   ros2 interface package wheelchair_interfaces && \
>   ros2 interface package wheelchair_interfaces | wc -l'
> ```
>
> ⚠️ 不管用哪种方式，**必须记下实际用的发行版**。若最后只在 **Jazzy** 上跑通，
> 那只说明「Jazzy 通过」，**Humble 仍记为待验证**——Humble 才是本项目基线
> （标准 §4.1，Jazzy 仅作 SO-ARM 上游参考）。

### Ubuntu 22.04 原生环境

```bash
source /opt/ros/humble/setup.bash          # 没装 colcon 的话：apt install python3-colcon-common-extensions
colcon build --symlink-install --packages-select wheelchair_interfaces
source install/setup.bash
ros2 interface package wheelchair_interfaces
ros2 interface package wheelchair_interfaces | wc -l    # 应为 8
```

**期望结果**：列出 6 个 msg 和 2 个 action，一个不多一个不少（顺序可能不同，共 8 条）。

```
wheelchair_interfaces/action/ChangePosture
wheelchair_interfaces/action/GraspObject
wheelchair_interfaces/msg/McuState
wheelchair_interfaces/msg/RangeArray
wheelchair_interfaces/msg/SafetyStatus
wheelchair_interfaces/msg/StandState
wheelchair_interfaces/msg/SystemMode
wheelchair_interfaces/msg/VoiceIntent
```

再抽查一个字段定义是否完整：

```bash
ros2 interface show wheelchair_interfaces/msg/McuState
```

**通过之后要做两件事**（不改这两处，验证等于没做）：

1. 把 `docs/interfaces/README.md` 和标准附录 B 里该包的状态由「**待验证**」改成「已验证」，
   并附上构建的 ROS 2 发行版与日期；
2. 补掉 `wheelchair_ws/src/wheelchair_interfaces/package.xml:14` 的占位邮箱 `todo@example.com`。

## 自检 2 · 文档一致性（**只读，随时可跑**）

标准正文与注册表是否还对得上。这个脚本**只看不写**，随便跑。

```bash
python3 tools/check_iw_if_std_001.py
```

**期望结果**：退出码 `0`，末尾打印「全部校验通过。」，且逐项如下：

```
[1] 题注完整性与引用可解析
  [v] 题注 40 条，与 40 个表格对象一一对应
  [v] 图题注 1 条：1
  [v] 正文引用 40 处表、1 处图，全部可解析

[2] 与 interface_registry.yaml 交叉比对
  [v] 表 4-3 覆盖注册表全部 33 条 Topic
  [v] 表 4-4 覆盖注册表全部 7 条 Service 与 Action
  [v] 表 5-1 覆盖注册表全部 16 条 frame
  [v] 表 6-3 覆盖注册表全部 12 条消息编号

[3] 示例帧 CRC 复算（标准 §6.6）
  [v] 帧长自洽：LENGTH=6，总长 17 字节
  [v] 示例帧 CRC 复算 0x8122，与注册表一致（低字节先发）
  [v] 载荷解释：linear_x=200 mm/s  angular_z=0 mrad/s  timeout_ms=200
```

退出码非 0 就是有 `[x]` 项，**按提示改，别绕过**。数字对不上时先问自己：是不是改了正文某张表但没同步注册表？

> ⚠️ **只做检查的话，到这里就够了，不要再往下跑生成脚本。**
> `tools/gen_iw_if_std_001.py` 会**重新生成 docx**。同一份内容重生成的 docx 字节不同
> （zip 时间戳变了），提交时会产生一堆没有意义的 diff。**只有当你确实改了正文内容，才跑生成脚本。**

## 自检 2b · 改了正文才需要跑的

```bash
python3 tools/gen_iw_if_std_001.py     # 重出标准 docx
python3 tools/check_iw_if_std_001.py   # 再校验一遍，必须仍然退出码 0
```

改正文的正确顺序是：**改生成脚本 → 重出 docx → 跑校验 → 同步注册表 → 提交**。
生成脚本 `tools/gen_iw_if_std_001.py` 是正文的**唯一来源**，不要直接编辑 docx。

## 自检 3 · 渲染检查（需要装了 Word 的 Windows 机器）

docx 内容没问题，不代表打印出来没问题。导出 PDF 后看三处：

1. **有没有内容压到页脚**（本版 34 页，正常应全部在下边距以内）；
2. **表格跨页时表头有没有自动重复**；
3. **拉丁标识符有没有被换行切成 1~3 个字符的碎片** —— 有的话**调那一列的宽度，不要缩小字号**。
   （本版残留 5 处可接受的断词，都在下划线边界或长标识符尾部，属已知情况。）

## 自检 4 · 提交前（PR 门禁）

推送前逐条过一遍，这些都是会被人打回来的：

- [ ] 没有提交 `build/`、`install/`、`log/`
- [ ] 没有提交模型大文件、录制数据
- [ ] 没有提交 **API 密钥、密码、校园内网地址、个人绝对路径**（标准 §10.1 / §8.3）
- [ ] 改动走 **PR**，没有直推 `main` / `develop`
- [ ] PR 描述按 `.github/pull_request_template.md` 填写，**AI 工具使用记录**一栏照实写
- [ ] 若改了任何接口字段，**先提 ICR**（`.github/ISSUE_TEMPLATE/icr.yml`），并在 PR 里附上编号
- [ ] 同步更新了 `docs/interfaces/interface_registry.yaml`

> **V1.x 内不得改变已有字段的含义、顺序或单位**（标准 §1.5 第 4 条）。
> 要改就必须走 ICR + 迁移评审，升主版本。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `ModuleNotFoundError: No module named 'docx'` | `pip install python-docx`（包名带横线，import 名不带） |
| `ModuleNotFoundError: No module named 'yaml'` | `pip install pyyaml` |
| `colcon: command not found` | 忘了 `source /opt/ros/humble/setup.bash`；或 `apt install python3-colcon-common-extensions` |
| `ros2 interface package` 找不到该包 | 忘了 `source install/setup.bash`；或构建其实失败了，回看上一步输出 |
| 校验报「题注 N 条，表格对象 M 个，数量不符」 | 有人往正文加了表但没补题注。题注格式必须是独立的 `表 N-M 标题` 段落 |
| 校验报「以下引用找不到对应题注」 | 正文引用了不存在的表号，多半是表号重编时漏改；查 `docs/interfaces/表号映射表.md` |
| 校验报「示例帧 CRC 复算得 0xXXXX，注册表登记 0xYYYY」 | 帧结构或载荷被改动过。CRC 覆盖范围是 **VERSION 至 PAYLOAD**（不含 SOF 与 CRC 本身），先确认这个 |
| 校验报「表 4-3 缺少注册表中的 Topic」 | 正文话题表与注册表脱钩了。两边以注册表为准，补正文 |
| 校验有 `[!]` 开头的提示 | 提示不是错误，不影响退出码。但**别忽略**，先判断是不是真问题 |
