## 注册表维护规则

标准 §8.3 规定：**涉及 Topic、Service、Action、TF、串口或参数的改动，
必须同步更新 `interface_registry.yaml`**，否则 PR 不予合并。

任何条目变更都必须附带 ICR 编号（`.github/ISSUE_TEMPLATE/icr.yml`）。

### 版本规则（标准 §8.5）

| 变更 | 版本示例 | 处理方式 |
|---|---|---|
| 修正文档错字、实现缺陷，不改变接口 | 1.0.0 -> 1.0.1 | 补丁版本 |
| 新增兼容 Topic、可选字段或诊断项 | 1.0 -> 1.1 | 次版本，旧调用仍可工作 |
| 修改类型、字段顺序、单位、语义或删除接口 | 1.x -> 2.0 | 主版本，**必须迁移评审** |

**V1.x 内不得改变已有字段含义**（标准 §1.5 第 4 条）。

### V1.1 相对 V1.0 的注册表变化

- `serial.payloads.SAFETY_STATE` 末尾追加 `posture_enabled`（偏移 16，uint8）→ 载荷 16 变 17 字节。
  帧头 `VERSION` 仍为 `0x01`，接收端**必须按 `LENGTH` 判定长度**并同时容忍 16 与 17 两种值。
- 新增 `nan_policy` 段：登记允许用 NaN 表示「未知」的字段，以及串口哨兵 `0xFFFF`
  必须由 `serial_bridge` 转为 NaN（**不得缩放为 65.535 m**）。
- `serial.frame` 中 `VERSION` 的说明改为「长度一律按 LENGTH 判定」，与上一条配套。
- `fault_bits` 注明 `SafetyStatus` 与 `StandState` 共用标准表 12 定义及其适用范围。
- `/tf` 条目加注 QoS 待决风险，并记入 `pending_icrs` 的 ICR-003。

## V1.1 附录 B 交付检查表的状态代拟

标准 V1.1 附录 B 原来是 9 行「待确认／待创建／待验证／待归档」，与实际进度脱节。
本次按仓库实况代拟了状态，每行附核实依据。两个判断口径需注意：

- **「IW-IF-STD-001 V1.0 评审」记为已完成**——完成标准写的是「完成评审意见并**签字或**
  在 Git 留痕」，二者取一即可，本报告入库即满足留痕。**各组会签尚未办理**，
  若项目要求纸质或电子签章，需另行走该流程。
- **「wheelchair_interfaces ROS 2 包」记为待验证而非已完成**——完成标准是
  「msg srv action 可独立构建」，而本包尚未在真实 ROS 2 环境中执行过
  `colcon build`。定义齐全不等于构建通过。
